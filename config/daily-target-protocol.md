# +U/u Daily Target Protocol

This non-deployed policy describes safe daily SEO and learning targets for the
static Universe architecture. It contains no target list, keyword, query,
person, account, domain, credential, or private evidence. Keep those details
only in an access-controlled system outside the public artifact and repository
history.

## Boundary

A generated `?u=+U-...` value is a private device-local return link only. It
does not authenticate an operator, grant access, identify a person, reveal or
activate a target, count a contribution, or become an SEO identifier.

The local Fresh Launch Window's midnight, 12-hour, and 1,000-interaction rules
reset only browser presentation state. They cannot activate or deactivate a
target, publish content, modify an external service, or change a public page.

## State model

Each private target follows this state sequence:

`draft -> reviewed -> activated -> evaluated -> archived`

Only a responsible human may move a target forward. Review requires rights,
safety, accuracy, accessibility, capability, and public-value checks.
Activation requires a deliberate code or configuration change, human review,
and manual deployment. It is never scheduled, triggered by a page load,
visitor, query string, payment, social event, or automated signal.

## Public release and pause

Do not show a public target or CTA until an activated, safe, public-facing
page, guide, or template exists. A public invitation must be anonymous,
non-financial, and link only to that implemented material. It must not collect
search terms, track visitors, auto-publish, auto-rank-manipulate, or create
rewards or payments.

Before release, confirm the public URL is canonical, intentional, accessible,
included in the static artifact, and added to `sitemap.xml` only when active.
Confirm robots rules exclude non-public paths and no query-string return link
appears in a canonical URL, sitemap, or public log.

To pause or roll back, a human removes the public implementation and its
sitemap entry in a reviewed change, deploys manually, and records the private
reason and revision. Do not delete provenance, undo an external action, or
automatically change any target state.

## Evidence and evaluation

Keep only the minimum private provenance needed to support a decision: source,
rights basis, review date, responsible reviewer, public revision, and
human-reviewed aggregate visibility or feedback. Do not import personal search
data, profiles, direct messages, credentials, analytics exports, or
third-party content without permission.
